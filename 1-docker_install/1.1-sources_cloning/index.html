    ThothAI installation – preliminary activities

    ThothAI must be deployed as a Docker container to ensure isolation and manageability in the production environment. The only prerequisites are the availability of Python 3.13 or higher and the availability of Docker and the docker-compose client.

    Python and Docker installation

    The procedures for installing Python are outside the scope of this document. Visit the Python website for information on how to install or upgrade Python, if you have not already done so.

    Likewise, installing Docker and the docker-compose client is outside the scope of this document. Visit the Docker website for information on how to install Docker, if it is not already available.

    1 - Preliminary step – cloning the repository

    The installation requires first of all obtaining the project sources. ThothAI consists of a single repository that contains both the backend and the frontend.

    From the command line, move to the directory where you want to install and clone the repository:

    git clone https://github.com/mptyl/Thoth.git ThothAI
cd ThothAI

    After cloning, the project structure will look like this:

    ThothAI/
├── backend/                # Django application (backend)
├── frontend/               # Next.js application (frontend)
├── docker/                 # Docker configuration files
├── scripts/                # Installation and configuration scripts
├── config.yml              # Configuration template
├── .env.local.template     # Environment variables template
└── ...

    2 - Preliminary step – basic configuration

    2.1 - Preparing the configuration file

    The first mandatory step for installing ThothAI is to create your personal configuration file starting from the provided template:

    cp config.yml config.yml.local

    The config.yml.local file contains all the settings required for ThothAI to operate. You will need to configure:

    • AI Providers: Enable at least one LLM provider, choosing one or more among OpenAI, Anthropic, Gemini, Mistral, DeepSeek, OpenRouter, Ollama and LMStudio. It is recommended to configure at least OpenRouter in order to use the default workspace, which is set up to use models provided by OpenRouter. Alternatively, you can choose direct providers (OpenAI, Anthropic, etc.), but if you want to use the demo workspace, you must configure the Models and Agents that use the providers you enabled;
    • Embedding service: Configure the embedding service used by Qdrant and by the LSH management. Choose among the embeddings provided by OpenAI, Mistral or Cohere;
    • Backend base model: Choose the base model for backend‑managed activities such as generating table and column descriptions, database documentation, ERD creation, etc. Specify the provider and the model;
    • Databases used: Specify the databases you plan to use. You can work with SQLite, MariaDB, MySQL, PostgreSQL, Informix and SQL Server databases;
    • Admin credentials: Set username/password for the administrative access of the admin user, which is created by default when the docker-compose up -d command is executed;
    • Demo credentials: Set username/password for the demo user, which can be used immediately to try the software without having to configure anything;
    • Monitoring: Configure Logfire for application monitoring (see monitoring), indicating whether you intend to use the Logfire monitoring service and, if so, the access token;
    • Service ports: Configure the ports for the various components, if the default ones conflict with services already running on those ports;
    • Docker configuration: Configure Docker options – if you plan to use a custom Docker network, specify the network name;
    • Runtime: Configure runtime options such as Django working mode (debug or not) and separate log levels for frontend and backend.

    Recommended LLM provider to get started

    For a quick trial of ThothAI, it is recommended to use OpenRouter, which provides access to hundreds of LLMs with a single API key and also includes free models. The Docker installation of ThothAI creates a demo environment already preconfigured to use OpenRouter as provider and california_schools as the practice database.

    3 - Preliminary step – obtaining API Keys

    Before proceeding with the actual installation, you need to obtain API Keys for:

    3.1 - LLM generation services

    ThothAI is set up to connect to the following LLM API providers:

    • OpenAI
    • Gemini (Google)
    • Anthropic
    • Mistral
    • DeepSeek
    • OpenRouter (which acts as a proxy to hundreds of providers)
    • LMStudio (when not running locally)
    • Ollama (when not running locally)

    Each API provider, in turn, allows the use of different models, which will need to be specified in the application setup.

    During configuration you must decide which providers you want to use. For each of them you need to obtain an API Key. If you use Ollama or LMStudio locally, no API Key is required; you only need to specify the IP address of the server used if it differs from the default.

    To obtain an API Key, follow the provider's procedures.

    Assigning an API Key

    The procedures for assigning an API Key are more or less the same for all providers. Create API Keys with any name you prefer, such as "ThothKey" or similar, for each provider you want to use. These keys must be specified in the config.yml configuration file if you want to use Docker, otherwise in the .env.local configuration file.

    If you use OpenRouter, with a single API Key you will have access to a long list of LLMs, with very different sizes and costs (some models are even available for free). Visit the OpenRouter website for additional details.

    Through OpenRouter you can use models from providers not listed above, since OpenRouter always exposes the same interface, compatible with the OpenAI interface, which can be used for all the models it supports.

    The default values set in ThothAI assume that all Agents involved in the various stages of the process use a model provided by OpenRouter.

    You can obviously change this setup (as we will see later), but if you want to quickly try ThothAI, the ideal approach is to start by purchasing 5 or 10 dollars of OpenRouter credit and keep the default settings defined during installation.

    From our tests, using the default configuration, which makes extensive use of inexpensive models in the less critical stages of the process, each execution costs between 2 and 5 US cents. Therefore, with about ten dollars, you can run between 200 and 500 executions of SQL generation from a natural language question.

    Costs of generating an SQL

    Obviously, the cost of generating an SQL depends on the number of Agents you want to run in parallel for SQL generation and verification tests. More Agents means a higher chance of obtaining a good SQL, but also a higher cost. Likewise, the larger and more powerful the models used, the higher the quality and speed of generation, and the higher the cost.

    3.2 - Logfire service

    Logfire is a service provided by Pydantic to track the activity of Python applications. Up to 10 million messages per month, the service is free.

    ThothAI logs its activity simultaneously to file, console and Logfire. The Logfire log persists for about 30 days and provides a high level of detail on the recorded operations.

    No data about the content of the queried databases is ever sent to Logfire, but if you do not want to use the service, simply leave the key empty and Logfire will not be used. In this case, only local log files will remain (see logs). However, you will not have the same level of granularity and insight provided by Logfire.

    If you want to use Logfire, you must go to Logfire and create an API Key. Choose a European server if you operate from a European country to have better performance. Save the server URL for future reference.

    Logging an LLM

    Logging the activities carried out by an LLM is quite a complex task. With Logfire you can easily inspect the prompt text received by the LLM, any tool invocations triggered by the running Agent, and the generated output, with plenty of detail.

    If you want to keep tight control over ThothAI's behavior, it is advisable to enable Logfire. The service can also be run locally, once the proper setup has been done, so any privacy issues can be addressed. For details, refer to the Logfire documentation.
