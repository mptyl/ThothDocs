# Installazione di ThothAI in locale

Local installation includes installing the Django backend, the SQL Generator (FastAPI) and the Next.js frontend.

!!! info "Local Development"

    Local execution uses `config.yml.local` as the primary configuration, which is automatically converted into `.env.local` by the `start-all.sh` script when the services are started.


!!! note "Django setup"

    How to set up a Django application is outside the scope of this documentation.
    See the [official Django deployment guide](https://docs.djangoproject.com/en/5.2/howto/deployment/) for further details.
    In this project we assume that a user interested in managing the backend in Developer mode knows Django well enough to be able to modify Thoth without difficulty.

## 1 - Sistema di Configurazione per Sviluppo Locale

### 1.1 - Configuration Files

#### config.yml.local (Main File)
- **Role**: Unified YAML configuration for all services (Docker and local)
- **Creation**: Copy from `config.yml` and customize
- **Contents**: API keys, local ports, service URLs, credentials, database flags
- **Usage**: Primary source from which `.env.local` is auto-generated

#### .env.local (Automatically Generated)
- **Role**: Env file generated by `start-all.sh` for local services
- **Generation**: Automatically via `scripts/generate_env_local.py`
- **Contents**: Environment variables extracted from `config.yml.local`
- **Note**: Do not edit it manually – edit `config.yml.local` instead.

### 1.2 - Local Configuration Flow

```
config.yml.local → start-all.sh → generate_env_local.py → .env.local
                        ↓                                      ↓
               validate_backend_ai.py                 export variabili
                        ↓                                      ↓
            update_local_db_dependencies.py          Servizi ereditano
                        ↓
                  uv sync (auto)
```

**Process:**

1. `start-all.sh` verifies/generates `.env.local` from `config.yml.local`
2. Forces `DEBUG=TRUE` for local development
3. Resolves database dependencies and automatically syncs with `uv` if needed
4. Validates AI provider and model
5. Exports variables into the shell environment (excluding generic PORT)
6. Starts the services (see 3.3 for list and URLs)

## 2 - Preparazione Ambiente

### 2.1 - Setting up the config.yml.local file

1. Copy the template:
```bash
cp config.yml config.yml.local
```

2. Edit `config.yml.local` with your own settings:
   - **LLM API keys** (at least one is required: OpenAI, Gemini or Anthropic)
   - **Embedding service** configuration
   - **Local ports** (if the default ones are taken)
   - **Database flags** (which databases to enable: sqlite, postgresql, mysql, informix)
   - **Admin credentials** (for the Django superuser)
   - Optional: **MERMAID_SERVICE_URL** (default: `http://localhost:8003`)

!!! warning "Do not modify .env.local directly"
    The `.env.local` file is auto-generated by `start-all.sh`. All changes must be made in `config.yml.local`.


### 2.2 - Installing uv (Required)

The project uses `uv` to manage Python and dependencies:

```bash
# Installare uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# Installare Python 3.13.5 (opzionale, uv lo farà automaticamente)
uv python install 3.13.5
```

!!! success "Dipendenze Auto-Gestite"
    `start-all.sh` sincronizza **automaticamente** tutte le dipendenze Python e Node.js quando necessario:
    
    - **Backend Django**: `uv lock --refresh && uv sync` (se cambiano i database abilitati)
    - **SQL Generator**: `uv sync --frozen`
    - **Frontend**: `npm install` (se manca node_modules)
    - **Mermaid Service**: `npm install` (se manca node_modules)

### 2.3 - Manual Dependencies Installation (Optional)

If you prefer to install manually before running `start-all.sh`:

#### Django Backend
```bash
cd backend
uv sync
cd ..
```

#### SQL Generator
```bash
cd frontend/sql_generator
uv sync
cd ../..
```

#### Next.js Frontend
```bash
cd frontend
npm install
cd ..
```

#### Mermaid Service
```bash
cd docker/mermaid-service
npm install
cd ../..
```

!!! note "Not required"
    These steps are **optional** – `start-all.sh` will run them automatically if needed.

## 3 - Avvio Servizi con start-all.sh

### 3.1 - What start-all.sh does

The script automatically performs all the necessary steps:

1. ✅ Checks that `config.yml.local` exists
2. ✅ Generates/updates `.env.local` from `config.yml.local` (see 1.1)
3. ✅ Forces `DEBUG=TRUE` for local development
4. ✅ Resolves database dependencies and syncs with `uv` (see 2.3)
5. ✅ Validates AI provider and model (see 5.3)
6. ✅ Loads environment variables
7. ✅ Starts all services (see 3.3 for the list)
8. ✅ Verifies that each service is running correctly

### 3.2 - Basic Usage

```bash
# Dare permessi di esecuzione (solo prima volta)
chmod +x start-all.sh

# Avviare tutti i servizi
./start-all.sh
```

!!! tip "First Run"
    On the first run, the script auto-syncs dependencies (see 2.3) and creates/starts the Qdrant container. This may take a few minutes.

### 3.3 - Services Started

The script automatically starts:

- **Django Backend**: http://localhost:8200
- **SQL Generator**: http://localhost:8180
- **Frontend**: http://localhost:3200
- **Mermaid Service**: http://localhost:8003
- **Qdrant** (Docker): http://localhost:6334 (volume `qdrant_storage/` in the project root)

### 3.4 - Service Management

For shutdown and cleanup, see section 8 – Stopping services.

## 4 - Configurazione Database e Migrazioni

!!! warning "Migrations are not automatic"
    `start-all.sh` **does not** run Django migrations automatically. They must be run manually.

### 4.1 - Django Migrations

Run migrations the first time or after model changes:

```bash
cd backend
export $(grep -v '^#' ../.env.local | grep -v '^PORT=' | xargs)
uv run python manage.py migrate
```

### 4.2 - Creating a Superuser

To access the Django admin panel:

```bash
cd backend
export $(grep -v '^#' ../.env.local | grep -v '^PORT=' | xargs)
uv run python manage.py createsuperuser
```

!!! tip "Admin credentials from config.yml.local"
    Admin credentials can be preconfigured in `config.yml.local` (section `admin`).

## 5 - Troubleshooting

### 5.1 - Port Conflicts
If the default ports are taken, change them in `config.yml.local`:
```yaml
local:
  ports:
    backend: 8200
    sql_generator: 8180
    frontend: 3200
    mermaid_service: 8003
```

Poi riavviare `start-all.sh` che rigenererà `.env.local` automaticamente.

### 5.2 - Python Version
If `uv` uses the system Python instead of the managed one:
1. Check `.python-version` files in the directories (backend and frontend/sql_generator)
2. Explicitly install: `uv python install 3.13.5`
3. Recreate the venv: `rm -rf .venv && uv sync`

### 5.3 - Environment Variables
- **Primary configuration**: All variables must be configured in `config.yml.local`
- **Generic PORT**: Filtered by `start-all.sh` to avoid conflicts
- **API Keys**: Configured in `config.yml.local` (section `llm`)
- **Databases**: Enabled/disabled in `config.yml.local` (section `databases`)
- **BACKEND AI**: `start-all.sh` automatically validates provider/model via `scripts/validate_backend_ai.py`
- **Automatic regeneration**: If `config.yml.local` is newer than `.env.local`, it is regenerated

### 5.4 - Tool Requirements
- **SQL Generator**: requires `uv` to be installed
- **Mermaid Service**: requires Node.js v18+
- **Frontend**: requires Node.js v20+
- **Qdrant**: requires Docker running; exposes `localhost:6334`

## 6 - Differences: Docker vs Local

| Aspect | Docker | Local |
|--------|--------|-------|
| Config File | `config.yml.local` → `.env.docker` (auto) | `config.yml.local` → `.env.local` (auto) |
| Startup Script | `install.sh` | `start-all.sh` |
| Backend Port | 8040 | 8200 |
| SQL Gen Port | 8020 | 8180 |
| Frontend Port | 3040 | 3200 |
| Mermaid Service | dedicated container | Node.js process (port 8003) |
| Qdrant | container on Docker network | container exposed on localhost:6334 |
| Python | Isolated container | uv-managed 3.13.5 (local .venv) |
| Database | Docker volume | Local file (sqlite) or native connections |
| Dependencies | Built into container | Auto-sync from start-all.sh |
| DEBUG | Configurable | Always TRUE (forced) |

## 7 - Complete Setup Workflow

### 7.1 - First Installation

```bash
# 1. Clone the repository
git clone https://github.com/mptyl/ThothAI.git
cd ThothAI

# 2. Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# 3. Configure
cp config.yml config.yml.local
# Edit config.yml.local with your API keys and settings

# 4. Start everything (auto-installs dependencies)
chmod +x start-all.sh
./start-all.sh

# 5. Then run migrations and create the superuser as described in 4.1 and 4.2
```

### 7.2 - Daily Development

To start services in development, see 3.2 – Basic Usage.

### 7.3 - Updating Configuration

```bash
# 1. Edit config.yml.local
vim config.yml.local  # o altro editor

# 2. Restart start-all.sh
# The script detects the change and regenerates .env.local automatically
./start-all.sh
```

## 8 - Stopping services

- Press `Ctrl+C` in the `start-all.sh` shell
- When prompted, choose whether to stop the `qdrant-thoth` container as well
- The script cleanly stops all started services
