# ThothAI local installation – preliminary activities
**ThothAI** can be installed either as a `Docker` container, to work in an isolated and easily manageable production environment, or locally, to operate in a `'development'` context that makes it easy to implement and test customizations.

Prerequisites for local development:

- `Python 3.13` or higher
- `uv`, Python dependency manager ([installation](https://docs.astral.sh/uv/getting-started/){:target="_blank"})
- `Node.js v20+` / `npm` for the frontend and Node services
- `Docker` for the Qdrant service (vector DB) even when ThothAI is started locally

!!! note "Installing prerequisites"

    The procedures for installing Python, uv, Node.js and Docker are outside the scope of this document.
    Follow the links below to access the relevant installation procedures:
    
    - [Python](https://www.python.org/){:target="_blank"}
    - [uv](https://docs.astral.sh/uv/getting-started/){:target="_blank"}
    - [Node.js](https://nodejs.org/){:target="_blank"}
    - [Docker](https://www.docker.com/){:target="_blank"}

## 1 - Preliminary step – cloning the repository

The installation requires first of all obtaining the project sources.
**ThothAI** consists of a single repository that contains both backend and frontend.

From the command line, move to the directory where you prefer and clone the repository:

```bash
git clone https://github.com/mptyl/Thoth.git ThothAI
cd ThothAI
```

After cloning, the project structure will look like this:

```
ThothAI/
├── backend/                # Applicazione Django (backend)
├── frontend/               # Applicazione Next.js (frontend)
├── docker/                 # File di configurazione Docker
├── scripts/                # Script di installazione e configurazione
├── config.yml              # Template di configurazione
├── .env.local.template     # Template delle variabili d'ambiente
└── ...
```

## 2 - Preliminary step – basic configuration

### 2.1 - Preparing the configuration file {#preparazione-configurazione}

For local startup, the main configuration file is `config.yml.local`, which has the same structure as the one used for the Docker installation. The `start-all.sh` script reads this file and automatically generates the `.env.local` file required for execution.

**First mandatory step**: create your personal configuration file starting from the provided template:

```bash
cp config.yml config.yml.local
```

The `config.yml.local` file contains all the settings required for ThothAI to operate. You will need to configure:

- **AI Providers**: Enable at least one LLM provider, choosing one or more among OpenAI, Anthropic, Gemini, Mistral, DeepSeek, OpenRouter, Ollama and LMStudio
- **Embedding service**: Configure the embedding service used by Qdrant and LSH (OpenAI, Mistral or Cohere)
- **Backend base model**: Choose the base model for backend‑managed activities (descriptions, documentation, ERD, etc.)
- **Databases used**: Specify which databases you intend to use (SQLite, MariaDB, MySQL, PostgreSQL, Informix, SQL Server). Multiple databases can be used simultaneously.
- **Service ports**: Configure the ports for the various components if the default ones conflict with other services
- **Monitoring**: Optionally configure Logfire for advanced monitoring

!!! note "Recommended LLM provider to get started"

    For a quick trial of ThothAI, it is recommended to use **OpenRouter**, which provides access to hundreds of LLMs with a single API key and also includes free models. The default configuration is already set up to use OpenRouter.

#### 2.1.1 - Structure of the `config.yml.local` file

Below are the parameters currently present in the `config.yml` configuration file at the project root. Use them as a reference when preparing `config.yml.local`:

```yaml
version: "1.0"

ai_providers:

    enabled: false
    api_key: ""
  anthropic:
    enabled: false
    api_key: ""
  gemini:
    enabled: false
    api_key: ""
  mistral:
    enabled: false
    api_key: ""
  deepseek:
    enabled: false
    api_key: ""
    api_base: "https://api.deepseek.com/v1"
  openrouter:
    enabled: true
    api_key: ""
    api_base: "https://openrouter.ai/api/v1"
  ollama:
    enabled: false
    api_base: "http://127.0.0.1:11434"
  lm_studio:
    enabled: false
    api_base: "http://localhost:1234"
  groq:
    enabled: false
    api_key: ""

embedding:
  provider: "openai"
  api_key: ""
  model: "text-embedding-3-small"

backend_ai_model:
  ai_provider: "openrouter"
  ai_model: "google/gemini-2.5-flash"

databases:
  sqlite: true
  postgresql: true
  mysql: false
  mariadb: true
  sqlserver: true

ports:
  frontend: 3200
  backend: 8200
  sql_generator: 8180
  mermaid_service: 8003
  qdrant: 6334

monitoring:
  enabled: false
  logfire_token: ""

  debug: true
  backend_log_level: "INFO"
  frontend_log_level: "INFO"

```

#### 2.1.2 - Practical configuration of config.yml.local

After copying `config.yml` to `config.yml.local`, edit the file to add your API keys and settings.

**Minimum configuration to get started** (example with OpenRouter):

```yaml
ai_providers:
  openrouter:
    enabled: true
    api_key: "sk-or-v1-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"  # Inserire la propria API key
    api_base: "https://openrouter.ai/api/v1"

embedding:
  provider: "openai"
  api_key: "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"  # Inserire la propria API key OpenAI
  model: "text-embedding-3-small"

backend_ai_model:
  ai_provider: "openrouter"
  ai_model: "google/gemini-2.5-flash"
```

**The other sections** (`databases`, `ports`, `monitoring`, `runtime`, `relevance_guard`) can be left with their default values to get started.

!!! tip "Step-by-step configuration"

    1. **Enable at least one LLM provider**: Set `enabled: true` and add your `api_key`
    2. **Configure the embedding**: Add the API key for the chosen provider (OpenAI, Cohere or Mistral)
    3. **Check the backend AI model**: Ensure that `ai_provider` and `ai_model` match an enabled provider
    4. **Optional**: Change the ports if the default ones are already in use on your system
    5. **Optional**: Configure Logfire for advanced monitoring by setting `monitoring.enabled: true` and providing the token

!!! note "Automatic .env.local generation"

    **You do not need to manually create the `.env.local` file**. The `start-all.sh` script automatically reads `config.yml.local` and generates (or updates) the `.env.local` file required for local execution. If `config.yml.local` is modified, `.env.local` will be regenerated automatically at the next startup when you run `start-all.sh`.
    
    The generated `.env.local` file contains all the environment variables required for the services (API keys, ports, paths, etc.) and is automatically excluded from version control via `.gitignore`.

## 3 - Preliminary step – obtaining API Keys

Before proceeding with the actual installation, you need to obtain API Keys for:

### 3.1 - LLM generation services

**ThothAI** is ready to connect to the following LLM API providers:

* OpenAI 
* Gemini (by Google)
* Anthropic 
* Mistral
* DeepSeek
* LMStudio
* Ollama
* OpenRouter (which acts as a proxy to hundreds of providers)


Each API provider, in turn, allows the use of different models, which must be specified in the application setup.

During configuration you must decide which providers you want to use. For each of them you need to obtain an API Key.
If you use Ollama or LMStudio locally, of course, no API Key is required; you only need to indicate the IP of the server used if it differs from the default.

To obtain an API Key, follow the procedures provided by each provider.

!!! note "Assigning an API Key"

    The procedures for assigning an API Key are more or less the same for all providers.
    Create API Keys with any name you prefer, such as "ThothKey" or similar, for each provider you want to use. These keys must be specified in the `config.yml` configuration file if you want to use Docker, otherwise in the `.env.local` configuration file.

If you use OpenRouter, with a single API Key you can access a long list of LLMs with very different sizes and costs (some models are even available for free). Visit the [OpenRouter](https://openrouter.ai/) website for more details.

Through `OpenRouter` you can use models from providers not included in the previous list, since OpenRouter always exposes the same interface, compatible with the OpenAI interface, which can be used for all the models it supports.

The default values set in ThothAI assume that all Agents involved in the various stages of the process use a model provided by OpenRouter.

You can obviously change this setup (as we will see later), but if you want to quickly try ThothAI, the ideal approach is to start by purchasing 5 or 10 dollars of OpenRouter credit and keep the default settings defined during installation.

From our tests, using the default configuration, which makes extensive use of inexpensive models in the less critical stages of the process, each execution costs between 2 and 5 US cents, depending on the number of Agents you want to run in parallel (more Agents, higher probability of obtaining a good SQL, higher cost).
Therefore, with about ten dollars, you can perform between 200 and 500 executions.

### 3.2 - Logfire service

[Logfire](https://pydantic.dev/logfire) is a service provided by Pydantic to track the activity of Python applications. Up to 10 million messages per month, the service is free.  

ThothAI logs its activity simultaneously to file, console and Logfire. The Logfire log persists for about 30 days and provides a high level of detail on the recorded operations.

No data about the content of the queried databases is ever sent to Logfire, but if you do not want to use the service, simply leave the key empty and Logfire will not be used. In this case, only local log files will remain [(see logs)](../4-user_manual/4.3-logging/4.3.2-log_management.md). However, you will not have the same level of granularity and insight provided by Logfire.

If you want to use Logfire, you must go to [Logfire](https://pydantic.dev/logfire) and create an API Key. Choose a European server if you are operating from a European country to have better performance. Save the server URL for future reference.

!!! note "Logging an LLM"

    Logging the activities carried out by an LLM is quite a complex task. With Logfire you can easily inspect the prompt text received by the LLM, any tool invocations triggered by the running Agent in execution and the generated output, with plenty of detail.
    
    If you want to keep tight control over ThothAI's behavior, it is advisable to enable Logfire. The service can also be run locally, once the proper setup has been done, so any privacy issues can be addressed. For details, refer to the Logfire documentation.


## 4 - Preliminary step – checking software prerequisites

Before starting the services with `start-all.sh`, make sure that all software prerequisites are correctly installed:

### 4.1 - Checking Python and uv

```bash
# Check Python version (must be 3.13+)
python3 --version

# Check uv installation
uv --version
```

If `uv` is not installed, follow the instructions at [https://docs.astral.sh/uv/getting-started/](https://docs.astral.sh/uv/getting-started/){:target="_blank"}

### 4.2 - Checking Node.js and npm

```bash
# Check Node.js version (must be v20+)
node --version

# Check npm
npm --version
```

### 4.3 - Checking Docker

```bash
# Check Docker (required for Qdrant)
docker --version

# Check that Docker is running
docker ps
```

!!! warning "Docker is mandatory"

    Even for local installation, Docker is required to run the Qdrant service (vector database). Make sure Docker is installed and running before launching `start-all.sh`.
